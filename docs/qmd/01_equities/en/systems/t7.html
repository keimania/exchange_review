1. System Overview

Item Details
System Name T7
Operated By Deutsche BÃ¶rse AG (Xetra cash market) / Eurex Frankfurt AG (derivatives)
Purpose Unified high-performance trading platform serving the Xetra cash market, Eurex derivatives exchange, European Energy Exchange (EEX), BÃ¶rse Frankfurt, and Nodal Exchange
Launch Year December 2012 (Eurex derivatives – first deployment); July 2017 (Xetra cash market migration)
Current Version T7 Release 14.0 (introduced 10 November 2025 for Xetra and BÃ¶rse Frankfurt)
Vendor / In-house In-house (developed by Deutsche BÃ¶rse Group technology teams; built largely in-house at Eurex)

T7 is Deutsche BÃ¶rse Group’s core trading platform, designed to deliver low latency, high throughput, and flexibility across multiple asset classes and trading venues. The platform replaced Xetra’s legacy trading infrastructure (which had operated for nearly two decades across 16 release versions) and the previous Eurex derivatives system. A key differentiator is the shared platform architecture: the same T7 technology underpins both cash equities trading on Xetra and derivatives trading on Eurex, enabling synergies for participants active in both markets.

When first deployed at Eurex in 2012, T7 was reported to be 14 times faster than the previous platform.

2. Architecture

2.1 High-Level Design

  • Deployment model: On-premise, hosted at Equinix colocation facility in Frankfurt
  • Topology: Partition-based distributed matching architecture
  • Design pattern: High-performance, event-driven matching with independent product partitions
  • Multi-venue: Single platform serving Xetra (cash equities), Eurex (derivatives), EEX (energy), BÃ¶rse Frankfurt, and Nodal Exchange

T7 employs a partition-based architecture in which market services are separated into completely independent groups of products (partitions). Each partition operates its own matching engine and partition-specific gateway, providing both performance isolation and resilience benefits. If one partition experiences an issue, other partitions continue operating independently. Instruments are distributed across partitions (e.g., Xetra cash market uses multiple partitions, with German equities and non-German equities on separate partitions).

[Source: Xetra, “T7 Simulation: Increase in the number of partitions”, https://www.eurexgroup.com/dbcm-en/newsroom/circulars-newsletters/Xetra-circulars-mailings/T7-Simulation-Increase-in-the-number-of-partitions-and-change-of-the-Partition-ID-for-some-products-3836718, accessed 2026-04-06]

4. Interfaces & Protocols

4.1 Order Entry

Interface Protocol Description
Enhanced Trading Interface (ETI) Proprietary binary; FIX 5.0 SP2 semantics Primary high-performance interface; asynchronous message-based; TCP/IP; supports order handling, quote handling, RFQs, strategy creation, off-book trade entry; no special hardware required
FIX Gateway FIX 4.2 and FIX 4.4 Standard FIX protocol access for broader compatibility; Trading sessions (order management, risk control, cross trade) and Back-office sessions (trade confirmations)
FIX LF Interface FIX 4.4 only Newer FIX interface integrated closer to T7 architecture; provides similar infrastructure and performance characteristics as ETI; introduced with Release 9.0
T7 GUI (Trader) Web-based (transitioning from Java) Graphical trading interface for manual order entry; Java-based currently, web-based T7 Web Trader expected not before 2027

ETI Key Characteristics: - Asynchronous, message-based interface following FIX 5.0 SP2 semantics including user-defined fields (UDF) - Connection via TCP/IP to Application Gateways that host client sessions - No special hardware or exchange software installation required - Free choice of operating system, programming language, and compiler version - Session-oriented with gateway-managed sessions

FIX Gateway Key Characteristics: - Supports FIX 4.2 and FIX 4.4 protocols - ClOrdID must be unique per business day and trading session - Two session types: Trading session and Back-office session - Slightly higher latency than ETI due to additional protocol translation

4.2 Market Data Dissemination

Feed Protocol Description Content
EMDI (Enhanced Market Data Interface) UDP multicast; FAST 1.1/1.2 encoded Un-netted feed; disseminates every order book change up to configured depth Market-by-price (MBP) with aggregated depth at limited price levels; all on-exchange trades
MDI (Market Data Interface) UDP multicast; FAST encoded Netted/statistical market data Daily high/low price, total traded quantity, last trade information
EOBI (Enhanced Order Book Interface) UDP multicast; native binary (not FAST encoded) Full market-by-order feed; no depth limitation Side, price, priority timestamp, displayed quantity of each individual order/quote; trade price and quantity
RDI (Reference Data Interface) UDP multicast; FAST encoded Reference/static data Instrument definitions, trading parameters, product assignments
EMDS (Extended Market Data Service) UDP multicast Extended market data including settlement prices and open interest Trade prices, settlement prices, open interest data

Market Data Architecture: - All interfaces distribute information via UDP multicast - Dual service paths (Service A and Service B) with different multicast addresses provide live-live redundancy - Clients should subscribe to both services and arbitrate between them - EOBI is the premium feed for latency-sensitive participants – provides full order-by-order book without depth limitation and is not FAST encoded (reducing decode overhead) - EMDI provides un-netted updates (every order book change affecting in-scope price levels), while MDI is netted - FIX 5.0 SP2 semantics used across feeds (except EOBI which uses native binary format)

5. Resilience & Business Continuity

5.1 Redundancy

  • Partition independence: Each partition operates independently; a failure in one partition does not affect other partitions
  • Matching engine failover: Every matching engine process has a standby partner that can take over immediately if the primary fails; a matching engine failover triggers a market reset – the secondary component loads persistent orders from the persistency layer; all non-persistent orders and quotes are deleted
  • Market data redundancy: Dual multicast service paths (Service A and Service B) with different multicast addresses; live-live concept
  • Gateway redundancy: Multiple gateway sessions available; PS and LF gateways provide different access paths
  • Network redundancy: N7 network provides redundant connectivity across 35+ countries

6. Notable Technical Features

6.1 Shared Platform with Eurex Derivatives

T7 is notable for being a truly shared technology platform across both cash equities (Xetra) and derivatives (Eurex). This provides: - Common interface specifications (ETI, FIX, market data feeds) across cash and derivatives - Reduced development and maintenance costs for participants active in both markets - Shared colocation infrastructure at Equinix FR2 - Unified technology release cycle (releases deployed across both venues) - Extended to additional venues: EEX (energy), BÃ¶rse Frankfurt, Nodal Exchange, and licensed to external exchanges (e.g., Bombay Stock Exchange)

6.2 Volatility Interruption Mechanism

T7 implements a sophisticated volatility interruption system to strengthen price continuity: - Single Volatility Interruption model: Used for equities and equity-like securities; triggers an unscheduled auction when the potential next price deviates too far from reference prices - Volatility Interruption with Automated Corridor Expansion (ACE): Used for ETFs, ETNs, and ETCs; multi-level price corridors (narrow to wide) defined per instrument; if no valid price is found within the current corridor, the interruption extends and switches to the next wider corridor - Operates in both auctions and continuous trading - Price determination during interruption follows the principle of most executable volume

[Source: Xetra, “Volatility Interruption during continuous trading”, https://www.xetra.com/xetra-en/trading/protective-mechanisms/protective-mechanisms-in-continuous-trading, accessed 2026-04-06] [Source: Xetra, “Protective Mechanisms”, https://www.xetra.com/xetra-en/trading/protective-mechanisms, accessed 2026-04-06]

6.3 Designated Sponsor Integration

The Designated Sponsor program is a key liquidity mechanism integrated into T7: - Designated Sponsors post binding buy and sell offers for less liquid securities - Must observe maximum spread, minimum quote volume (lot size on both sides), and minimum quotation duration - Minimum presence requirements: 80% for ETFs/ETPs, 90% for equities (in both auctions and continuous trading) - All firm quotes and two-way limit orders must be flagged with a “Liquidity Provision Indicator” - Subject to MiFID II / MiFIR Regulated Market Maker obligations - Deutsche BÃ¶rse issues a performance rating comparing Designated Sponsors based on quote duration, spread, and turnover - Sponsors must register for every ISIN-currency combination separately

[Source: Xetra, “Designated Sponsor and Market Maker”, https://www.cashmarket.deutsche-boerse.com/cash-en/trading/Xetra/Designated-Sponsor-and-Market-Maker, accessed 2026-04-06] [Source: Xetra, “Designated Sponsor Guide”, https://www.xetra.com/resource/blob/3452184/75f9eefb7b59e0464dc34c3658e1549b/data/designated-sponsor-guide.pdf, accessed 2026-04-06]

6.4 T7 Entry Services (TES)

T7 Entry Services enable participants to enter order/trade information into the T7 system, providing: - A channel for negotiated or off-book trades to be reported into the exchange - Two types of TES services offered - Integration with the clearing workflow through T7

[Source: Xetra, “Xetra T7 Entry Service”, https://www.xetra.com/xetra-en/trading/trading-models/xetra-entry-service, accessed 2026-04-06]

6.5 N7 Network and Cloud Connectivity

  • N7 network: Deutsche BÃ¶rse’s global network infrastructure providing connectivity to T7; thousands of connections across 35+ countries in Europe, North America, and Asia
  • Cloud simulation: T7 provides a cloud-based simulation environment for participants to test; current cloud simulation environment scheduled for migration on 28 March 2026
  • Connectivity options: Colocation at Equinix FR2 (lowest latency), proximity hosting, leased line via N7, and internet-based access for non-latency-sensitive use cases

[Source: Deutsche BÃ¶rse, “N7”, https://www.deutsche-boerse.com/dbg-en/markets-services/ps-technology/ps-7-market-technology/ps-n7, accessed 2026-04-06]

6.6 Technology Licensing / Export

T7 technology has been licensed to external exchanges, including: - Bombay Stock Exchange (BSE, India) - This positions Deutsche BÃ¶rse alongside a small group of exchange operators (including KRX, Nasdaq, and LSE Group) that export their trading technology

Key Differentiators

T7 Strengths: 1. Partition-based architecture: Independent partitions provide strong fault isolation – a failure in one product group does not cascade to others; each partition has its own matching engine and gateway 2. Shared cash/derivatives platform: Single technology serving both Xetra cash and Eurex derivatives reduces integration costs for cross-market participants 3. Extremely low internal latency: Minimum internal matching latency of ~2.8 microseconds is among the fastest globally 4. Comprehensive market data: Four distinct market data interfaces (EMDI, MDI, EOBI, RDI) offer participants flexibility to choose data granularity and latency profile 5. Volatility Interruption with ACE: Multi-level corridor expansion for ETFs/ETPs is a sophisticated safeguard mechanism 6. Global network reach: N7 network provides direct connectivity from 35+ countries 7. Extensive public documentation: Deutsche BÃ¶rse publishes unusually detailed technical documentation about T7 internals, latency performance, and system dynamics

KRX Exture+ Strengths: 1. Broader asset class unification: Single platform handles equities, bonds, and all derivatives classes within one exchange 2. Technology independence: Fully in-house development with owned data center infrastructure (Busan) 3. Technology export track record: KRX has established a broader export footprint (Laos, Cambodia, and others) 4. Simpler venue model: Single exchange covering all Korean capital market products reduces cross-venue complexity 5. Competitive latency: ~70 microseconds matching engine latency is globally competitive, though T7’s internal figures are faster

Architectural Comparison: - T7’s partition model provides strong fault isolation but requires careful instrument-to-partition assignment and may involve different latency profiles across partitions; KRX’s unified model may offer more uniform latency characteristics across all instruments - T7’s approach of hosting at a third-party Equinix facility differs from KRX’s owned Busan Data Center – the Equinix model provides access to a broader colocation ecosystem but introduces a dependency on a third-party facility operator - T7’s shared platform across cash and derivatives is architecturally similar to KRX’s unified approach, but spans legally separate exchanges (Xetra and Eurex) while KRX operates as a single integrated exchange - Both exchanges conduct regular DR testing; T7’s approach of re-using simulation infrastructure as DR is a pragmatic but potentially capacity-constrained design compared to dedicated DR facilities - T7’s EOBI (full order-by-order book feed) is comparable to KRX’s order book data feeds; both provide transparency for high-frequency participants
