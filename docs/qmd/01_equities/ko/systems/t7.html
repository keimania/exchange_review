1. 시스템 개요 (System Overview)

항목 세부 내용
시스템명 T7
운영 기관 Deutsche Boerse AG (Xetra 현물시장) / Eurex Frankfurt AG (파생상품)
목적 Xetra 현물시장, Eurex 파생상품거래소, European Energy Exchange (EEX), Boerse Frankfurt, Nodal Exchange를 서비스하는 통합 고성능 매매 플랫폼
출시 연도 2012년 12월 (Eurex 파생상품 – 최초 배포); 2017년 7월 (Xetra 현물시장 이관)
현재 버전 T7 Release 14.0 (2025년 11월 10일 Xetra 및 Boerse Frankfurt에 도입)
개발 방식 자체 개발 (Deutsche Boerse Group 기술팀; Eurex에서 대부분 자체 구축)

T7은 Deutsche Boerse Group의 핵심 매매 플랫폼으로, 다수의 자산군 및 매매 거래소에 걸쳐 저지연, 고처리량, 유연성을 제공하도록 설계되었다. 이 플랫폼은 Xetra의 레거시 매매 인프라(거의 20년에 걸쳐 16개 릴리스 버전으로 운영)와 이전 Eurex 파생상품 시스템을 대체하였다. 주요 차별점은 공유 플랫폼 아키텍처로, 동일한 T7 기술이 Xetra 현물주식 매매와 Eurex 파생상품 매매 양쪽을 구동하여 양 시장에서 활동하는 참가자에게 시너지를 제공한다.

2012년 Eurex에 최초 배포 시 T7은 이전 플랫폼보다 14배 빠른 것으로 보고되었다.

[Source: Xetra, “T7 trading architecture”, https://www.xetra.com/xetra-en/technology/t7, accessed 2026-04-06]

시스템 변천사 (System Evolution)

기간 시스템 / 버전 주요 변경사항
1997년 Xetra (원본) Xetra 전자매매 출범; 대부분 종목에서 프랑크푸르트 플로어 기반 매매 대체
1997–2017 Xetra Releases 1.0–16.0 ~20년에 걸쳐 16개 연속 릴리스; 지연시간, 용량, 기능의 점진적 개선
2012년 12월 T7 Release 1.0 (Eurex) Eurex 파생상품거래소에 T7 최초 배포; 단계적 상품 이관; 전작 대비 14배 빠름
2017년 7월 T7 Release 5.0 (Xetra) Xetra 현물시장이 T7으로 이관; 레거시 Xetra 인프라 대체
2018년 1분기 Partition-Specific (PS) Gateway PS 게이트웨이 도입; 지연시간 변동성 대폭 감소
2020년 1분기 매매체결엔진 (매칭엔진) 하드웨어 업그레이드 매매체결엔진용 서버 하드웨어 업그레이드 완료
2021년 상반기 통합 매처/게이트웨이 매매체결엔진과 PS Gateway 프로세스를 동일 서버에 통합; 더 빠른 주문 처리 및 향상된 안정성
2025년 5월 T7 Release 13.1 Xetra 및 Boerse Frankfurt에 도입
2025년 11월 T7 Release 14.0 Xetra 및 Boerse Frankfurt 현행 운영 릴리스; 신규 웹 기반 GUI 도입
2026–2027 웹 GUI 전환 T7 Web Admin (2026년 2/3분기), T7 Web Trader (2027년 이전 불가); Java 기반 GUI의 단계적 대체

2. 아키텍처 (Architecture)

2.1 상위 수준 설계 (High-Level Design)

  • 배포 모델: 온프레미스, 프랑크푸르트 Equinix 코로케이션 (전산센터 공동입주) 시설에 호스팅
  • 토폴로지: 파티션 기반 분산 매칭 아키텍처
  • 설계 패턴: 독립적 상품 파티션을 갖는 고성능 이벤트 기반 매칭
  • 다중 거래소: Xetra (현물주식), Eurex (파생상품), EEX (에너지), Boerse Frankfurt, Nodal Exchange를 서비스하는 단일 플랫폼

T7은 시장 서비스가 완전히 독립적인 상품 그룹(파티션)으로 분리되는 파티션 기반 아키텍처를 채택한다. 각 파티션은 자체 매매체결엔진과 파티션별 게이트웨이를 운영하여 성능 격리와 복원력 양쪽의 이점을 제공한다. 한 파티션에서 문제가 발생해도 다른 파티션은 독립적으로 계속 운영된다.

2.2 핵심 구성요소 (Core Components)

구성요소 기능 기술
매매체결엔진 (파티션별) 파티션에 배정된 종목의 주문 매칭; 가격-시간 우선; 경매 및 연속매매 지원 맞춤형; 전용 서버 하드웨어에서 구동; 각 파티션이 대기 파트너를 갖는 자체 매매체결엔진 보유
Partition-Specific (PS) Gateway 최저 지연시간 주문 입력 경로; FIFO 처리; 파티션당 하나의 PS 게이트웨이, 2021년 상반기부터 매매체결엔진과 동일 서버에 통합 독자적 바이너리; TCP/IP; 2018년 1분기 도입
Low-Frequency (LF) Gateway 초저지연이 필요하지 않은 참가자용 주문 입력; 모든 파티션에 연결; PS 게이트웨이 대비 ~12 마이크로초 추가 지연시간 독자적 바이너리 (ETI); TCP/IP
Enhanced Trading Interface (ETI) 주요 고성능 매매 인터페이스; 비동기 메시지 기반; 독자적 세션 프로토콜에 FIX 프로토콜 (금융정보교환 규약) 5.0 SP2 의미론 TCP/IP 위 바이너리; 특수 하드웨어 불요; OS/언어 무관
FIX Gateway 표준 FIX 프로토콜 접근 (FIX 4.2 및 FIX 4.4); 매매 및 백오피스 세션 TCP/IP 위 FIX 4.2/4.4; FIX LF 인터페이스 (FIX 4.4 전용) Release 9.0에서 도입
시장 데이터 인터페이스 (EMDI/MDI/EOBI/RDI) 멀티캐스트를 통한 실시간 시장 데이터 배포 UDP 멀티캐스트; FAST 프로토콜 (FIX 스트리밍 압축 규약) 1.1/1.2 인코딩 (EOBI 제외); 이중 서비스 경로 (A 및 B)
리스크 엔진 (Risk Engine) 사전 매매 리스크 통제; 세션 수준 스로틀링; 포지션 한도 게이트웨이 계층에 통합
T7 GUI (Trader/Admin/Clearer) 매매, 관리, 청산 업무를 위한 그래픽 사용자 인터페이스 Java 기반에서 웹 기반 GUI로 전환 중 (2025–2027)

2.3 기술 스택 (Technology Stack)

계층 기술
프로그래밍 언어 C/C++ [미검증; Deutsche Boerse 기술 발표 및 업계 표준과 일치]
운영체제 Linux [미검증; 거래소 매매체결엔진의 업계 표준과 일치]
하드웨어 맞춤 최적화된 상용 서버 하드웨어; 2020년 매매체결엔진 하드웨어 업그레이드; 4–5 ns RMS 정확도의 PTP(Precision Time Protocol) 타이밍
FPGA (현장프로그래머블게이트어레이) 가속 T7 핵심 매매체결엔진에서 미확인; 서드파티 벤더(예: NanoSpeed)가 T7 접속용 FPGA 기반 연결 솔루션 제공
네트워크 N7 네트워크 인프라; 유럽, 북미, 아시아 35개 이상 국가에서 수천 개 연결 제공; 10G/100G 이더넷 연결
메시징 형식 FIX 5.0 SP2 의미론을 따르는 바이너리 메시지; 시장 데이터에 FAST 1.1/1.2 인코딩(EOBI 제외)
바이트 순서 Little Endian
코로케이션 Equinix FR2 데이터센터, 프랑크푸르트, 독일

3. 성능 사양 (Performance Specifications)

현재 지연시간 (운영 데이터, 2025년 2/3월) (Current Latency)

지표 값 조건
최소 내부 매칭 지연시간 ~2,787 ns (~2.8 마이크로초) 시장 데이터 타임스탬프에서 요청 처리까지 측정; 2025년 2월 운영 데이터
중앙값 왕복 (고빈도 세션) ~60 마이크로초 PS 게이트웨이 경유; 네트워크 전송 포함
LF 게이트웨이 추가 지연시간 ~12 마이크로초 PS 게이트웨이 경로 대비
PTP 타이밍 정확도 4–5 ns RMS Precision Time Protocol 동기화

참고사항: - 2,787 ns 최소값은 시장 데이터 생성과 주문 요청 처리 사이의 내부 매매체결엔진 처리 시간을 나타냄 - 게이트웨이 수준에서 측정된 왕복 지연시간은 네트워크 스택 오버헤드 포함; 실제 매매체결엔진 내부 지연시간은 이보다 현저히 낮음 - PS 게이트웨이(파티션별)는 단일 파티션의 매매체결엔진에 직접 연결하여 최저 지연시간 경로 제공

[Source: Deutsche Boerse, “Internal T7 Latency Performance Updates”, https://www.deutsche-boerse.com/resource/blob/4680836/55df581501c18919e9d72aa949ed03d9/data/T7%20Latency.pdf, accessed 2026-04-06]

처리량 및 용량 (Throughput & Capacity)

지표 값 비고
통상 처리량 (t_3n) ~8,000 kHz (800만 건/초) 내부 매매체결엔진 처리량; 2025년 3월 데이터
일일 최대 요청 12.5억 건 2025년 4월 7일 기록 (2023년 8.57억 건 대비)
최대 입력 속도 201,000건/초 2025년 6월 5일 기록 [미검증 – 전 T7 거래소 합산일 수 있음]
가동률 99.99%+ 주요 유럽 거래소의 업계 표준 목표 [미검증 – 구체적 SLA 미공개]

성능 진화 (Performance Evolution)

기간 개선사항 비고
2012년 12월 (Eurex T7 출시) 전작 대비 14배 빠름 최초 T7 배포

2020년 1분기 매매체결엔진 하드웨어 업그레이드 매매체결엔진용 신규 서버 하드웨어

4. 인터페이스 및 프로토콜 (Interfaces & Protocols)

4.1 주문 입력 (Order Entry)

인터페이스 프로토콜 설명
Enhanced Trading Interface (ETI) 독자적 바이너리; FIX 5.0 SP2 의미론 주요 고성능 인터페이스; 비동기 메시지 기반; TCP/IP; 주문 처리, 호가 처리, RFQ, 전략 생성, 장외 매매 입력 지원; 특수 하드웨어 불요

4.2 시장 데이터 배포 (Market Data Dissemination)

피드 프로토콜 설명 내용
EMDI (Enhanced Market Data Interface) UDP 멀티캐스트; FAST 1.1/1.2 인코딩 비집계(Un-netted) 피드; 구성된 깊이까지 모든 호가장 변경 배포 제한된 가격 수준에서의 집계 호가잔량(MBP); 모든 장내 매매
MDI (Market Data Interface) UDP 멀티캐스트; FAST 인코딩 집계(Netted)/통계 시장 데이터 일일 최고/최저가, 총 체결수량, 최종 매매 정보
EOBI (Enhanced Order Book Interface) UDP 멀티캐스트; 네이티브 바이너리 (FAST 인코딩 아님) 깊이 제한 없는 전체 주문별(Market-by-Order) 피드 각 개별 주문/호가의 방향, 가격, 우선순위 타임스탬프, 표시 수량; 매매 가격 및 수량
RDI (Reference Data Interface) UDP 멀티캐스트; FAST 인코딩 기준/정적 데이터 종목 정의, 매매 파라미터, 상품 배정
EMDS (Extended Market Data Service) UDP 멀티캐스트 정산가 및 미결제약정 포함 확장 시장 데이터 매매 가격, 정산가, 미결제약정 데이터

시장 데이터 아키텍처: - 모든 인터페이스가 UDP 멀티캐스트를 통해 정보 배포 - 서로 다른 멀티캐스트 주소의 이중 서비스 경로(Service A 및 Service B)가 라이브-라이브 이중화 제공 - 클라이언트는 양 서비스 모두 구독하여 중재해야 함 - EOBI는 지연시간에 민감한 참가자를 위한 프리미엄 피드 – 깊이 제한 없는 전체 주문별 호가장 제공이며 FAST 인코딩되지 않아(디코딩 오버헤드 감소) - EMDI는 비집계 업데이트(범위 내 가격 수준에 영향을 미치는 모든 호가장 변경) 제공, MDI는 집계 - EOBI를 제외한 모든 피드에서 FIX 5.0 SP2 의미론 사용

4.3 드롭 카피 / 거래 보고 (Drop Copy / Trade Reporting)

  • 백오피스 FIX 세션이 사업 단위 수준에서 매매 확인 수신 제공
  • ETI가 매매 통지 및 체결 보고 메시지 지원
  • T7 Entry Services (TES)를 통한 장외 매매 보고 이용 가능

4.4 기준 데이터 (Reference Data)

  • Reference Data Interface (RDI)가 UDP 멀티캐스트를 통해 종목 정의 및 매매 파라미터 발행
  • Deutsche Boerse 웹사이트에서 상품 및 종목 기준 데이터 다운로드 가능
  • N7 Network Access Guide가 IP 주소 및 포트 구성 제공 (v.2.5, 2025년 1월 업데이트)

5. 복원력 및 업무연속성 (Resilience & Business Continuity)

5.1 이중화 (Redundancy)

  • 파티션 독립성: 각 파티션이 독립적으로 운영; 한 파티션의 장애가 다른 파티션에 영향을 미치지 않음
  • 매매체결엔진 장애 전환: 모든 매매체결엔진 프로세스가 주 프로세스 장애 시 즉시 인계 가능한 대기 파트너를 보유; 매매체결엔진 장애 전환 시 시장 리셋 발생 – 보조 구성요소가 영속 계층에서 영속 주문을 로드; 비영속 주문 및 호가는 삭제
  • 시장 데이터 이중화: 서로 다른 멀티캐스트 주소의 이중 멀티캐스트 서비스 경로(Service A 및 Service B); 라이브-라이브 방식
  • 게이트웨이 이중화: 다수의 게이트웨이 세션 이용 가능; PS 및 LF 게이트웨이가 서로 다른 접근 경로 제공
  • 네트워크 이중화: N7 네트워크가 35개 이상 국가에 걸쳐 이중 연결 제공

6. 주요 기술적 특징 (Notable Technical Features)

6.1 Eurex 파생상품과의 공유 플랫폼 (Shared Platform with Eurex Derivatives)

T7은 현물주식(Xetra)과 파생상품(Eurex) 양쪽에 걸친 진정한 공유 기술 플랫폼이라는 점에서 주목할 만하다. 이는 다음을 제공한다: - 현물 및 파생상품 전반에 걸친 공통 인터페이스 사양(ETI, FIX, 시장 데이터 피드) - 양 시장에서 활동하는 참가자의 개발 및 유지보수 비용 절감 - Equinix FR2에서의 공유 코로케이션 인프라 - 양 거래소에 걸친 통합 기술 릴리스 주기 - EEX(에너지), Boerse Frankfurt, Nodal Exchange 등 추가 거래소로 확장, Bombay Stock Exchange 등 외부 거래소에 라이선스

6.2 변동성 중단 메커니즘 (Volatility Interruption Mechanism)

T7은 가격 연속성을 강화하는 정교한 변동성 중단 시스템을 구현한다: - 단일 변동성 중단 모델: 주식 및 주식 유사 증권에 사용; 잠재적 차기 가격이 기준가에서 너무 벗어날 때 비정기 경매를 발동 - 자동 코리더 확장(ACE)이 포함된 변동성 중단: ETF, ETN, ETC에 사용; 종목별 정의된 다단계 가격 코리더(좁은 것에서 넓은 것); 현재 코리더 내에서 유효 가격을 찾지 못하면 중단이 연장되고 다음 넓은 코리더로 전환 - 경매 및 연속매매 양쪽에서 운영 - 중단 중 가격 결정은 최대 체결 가능 수량 원칙에 따름

6.3 지정 스폰서 통합 (Designated Sponsor Integration)

지정 스폰서 프로그램은 T7에 통합된 핵심 유동성 메커니즘이다: - 지정 스폰서가 저유동성 증권에 대해 구속력 있는 매수/매도 호가 게시 - 최대 스프레드, 최소 호가 수량(양측 매매 단위), 최소 호가 지속시간 준수 의무 - 최소 존재 요건: ETF/ETP 80%, 주식 90% (경매 및 연속매매 양쪽) - 모든 확정 호가 및 양방향 지정가 주문에 “유동성 공급 지표(Liquidity Provision Indicator)” 표기 의무 - MiFID II / MiFIR 규제시장 마켓메이커 의무 적용 - Deutsche Boerse가 호가 지속시간, 스프레드, 거래대금에 기반한 지정 스폰서 성과 평가 발행

6.4 T7 Entry Services (TES)

T7 Entry Services는 참가자가 T7 시스템에 주문/매매 정보를 입력할 수 있게 한다: - 협상 또는 장외 매매를 거래소에 보고하는 채널 제공 - 두 가지 유형의 TES 서비스 제공 - T7을 통한 청산 워크플로우와 통합

6.5 N7 네트워크 및 클라우드 연결 (N7 Network and Cloud Connectivity)

  • N7 네트워크: Deutsche Boerse의 글로벌 네트워크 인프라, T7 연결 제공; 유럽, 북미, 아시아 35개 이상 국가에서 수천 개 연결
  • 클라우드 시뮬레이션: T7이 참가자 테스트를 위한 클라우드 기반 시뮬레이션 환경 제공; 현재 클라우드 시뮬레이션 환경은 2026년 3월 28일 이전 예정
  • 연결 옵션: Equinix FR2 코로케이션(최저 지연시간), 프록시미티 호스팅, N7 경유 전용선, 비지연민감 사용을 위한 인터넷 기반 접근

6.6 기술 라이선싱 / 수출 (Technology Licensing / Export)

T7 기술은 외부 거래소에 라이선스되었으며, 다음을 포함한다: - Bombay Stock Exchange (BSE, 인도) - 이는 Deutsche Boerse를 매매 기술을 수출하는 소수의 거래소 운영자(KRX, Nasdaq, LSE Group 포함) 그룹에 포지셔닝한다

주요 차별화 요소 (Key Differentiators)

T7 강점: 1. 파티션 기반 아키텍처: 독립 파티션이 강력한 장애 격리 제공 – 한 상품 그룹의 장애가 다른 그룹에 전파되지 않음; 각 파티션이 자체 매매체결엔진과 게이트웨이 보유 2. 현물/파생상품 공유 플랫폼: Xetra 현물과 Eurex 파생상품 양쪽을 서비스하는 단일 기술로 교차 시장 참가자의 통합 비용 절감 3. 극히 낮은 내부 지연시간: ~2.8 마이크로초의 최소 내부 매칭 지연시간은 전 세계적으로 가장 빠른 수준 4. 포괄적 시장 데이터: 4가지 시장 데이터 인터페이스(EMDI, MDI, EOBI, RDI)가 참가자에게 데이터 세분도 및 지연시간 프로필 선택 유연성 제공 5. ACE가 포함된 변동성 중단: ETF/ETP에 대한 다단계 코리더 확장은 정교한 보호 메커니즘 6. 글로벌 네트워크 도달: N7 네트워크가 35개 이상 국가에서 직접 연결 제공 7. 광범위한 공개 문서: Deutsche Boerse가 T7 내부, 지연시간 성능, 시스템 동적에 대해 이례적으로 상세한 기술 문서 공개

KRX Exture+ 강점: 1. 광범위한 자산군 통합: 단일 플랫폼이 하나의 거래소 내에서 주식, 채권, 모든 파생상품 클래스를 처리 2. 기술적 독립성: 자체 보유 데이터센터 인프라(부산)를 갖춘 완전한 자체 개발 3. 기술 수출 실적: KRX가 보다 넓은 수출 기반 구축 (라오스, 캄보디아 등) 4. 단순한 거래소 모델: 모든 한국 자본시장 상품을 포괄하는 단일 거래소로 교차 거래소 복잡성 감소 5. 경쟁적 지연시간: ~70 마이크로초 매매체결엔진 지연시간은 전 세계적으로 경쟁력 있으나, T7의 내부 수치가 더 빠름

아키텍처 비교: - T7의 파티션 모델은 강력한 장애 격리를 제공하지만 신중한 종목-파티션 배정이 필요하며 파티션 간 다른 지연시간 프로필이 발생할 수 있음; KRX의 통합 모델은 모든 종목에 걸쳐 보다 균일한 지연시간 특성을 제공할 수 있음 - T7의 서드파티 Equinix 시설 호스팅 방식은 KRX의 자체 보유 부산 데이터센터와 다름 – Equinix 모델은 보다 넓은 코로케이션 생태계 접근을 제공하지만 서드파티 시설 운영자에 대한 종속 도입 - T7의 현물 및 파생상품 공유 플랫폼은 KRX의 통합 접근방식과 아키텍처적으로 유사하지만, 법적으로 분리된 거래소(Xetra와 Eurex)에 걸쳐 있는 반면 KRX는 단일 통합 거래소로 운영 - 양 거래소 모두 정기적 DR 테스트 실시; T7의 시뮬레이션 인프라를 DR로 재활용하는 방식은 실용적이지만 전용 DR 시설 대비 용량이 제한될 수 있는 설계 - T7의 EOBI(전체 주문별 호가장 피드)는 KRX의 호가장 데이터 피드에 비교 가능; 양쪽 모두 고빈도 참가자에게 투명성 제공
