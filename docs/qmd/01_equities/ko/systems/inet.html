1. 시스템 개요 (System Overview)

항목 세부 내용
시스템명 NASDAQ INET (매매체결엔진 (매칭엔진) 핵심); Nasdaq Eqlipse (4세대 플랫폼 래퍼)
운영 기관 Nasdaq, Inc. (NDAQ)
목적 미국 주식(Nasdaq, BX, PSX)에 대한 초저지연 주문 매칭, 시장 데이터 배포 및 매매 체결; 전 세계 130개 이상의 시장에 라이선스 제공
출시 연도 2006년 (Instinet 인수 후 INET을 Nasdaq 주 매매체결엔진으로 채택); Eqlipse 플랫폼: 2024년
현재 버전 Nasdaq Eqlipse (4세대), INET 매매체결엔진 핵심
개발 방식 Nasdaq, Inc. 자체 개발. 원래 INET 엔진은 Instinet/Island ECN 기술(2005년 인수)에서 파생; 이후 세대는 스톡홀름(Genium INET), 시드니(X-Stream INET), 뉴욕/필라델피아 사무소에서 자체 개발

시스템 변천사 (System Evolution)

기간 시스템명 주요 변경사항
1971–1982 NASDAQ Automated Quotation System 체결 기능 없는 호가 전용 시스템; CRT 단말기에 마켓메이커의 매수/매도 호가 표시
1982–1990년대 SOES (Small Order Execution System) NASDAQ 최초의 전자 체결; 마켓메이커에 의무적; 소규모 주문만 해당
1997–2002 Island ECN / Instinet ECN Island ECN 출범(1996년) – 최초의 완전 전자 ECN 중 하나; 2002년 Instinet과 합병하여 Inet ECN 형성; 1초 미만 매칭; 표시 지정가 주문장을 선구적으로 도입
2002–2006 SuperMontage 마켓메이커 호가와 공개 지정가 주문을 통합한 NASDAQ의 통합 지정가 주문장; 개발비 1억 700만 달러; 인수 후 INET으로 대체
2005–2006 INET 채택 NASDAQ이 18.8억 달러에 Instinet 인수(2005년 12월 완료); Inet ECN 매매체결엔진 보유; SuperMontage에서 INET 플랫폼으로 모든 Nasdaq 매매 이관(2006년 완료); SuperMontage 퇴역
2007–2010 INET + OMX 기술 합병 NASDAQ이 OMX Group 인수(2007년), Genium 매매 플랫폼(스웨덴 기원) 확보; INET과 결합하여 글로벌 라이선싱용 Genium INET 생성; X-Stream INET 변형(호주 개발)도 개발
2010–2016 Genium INET / X-Stream INET 두 개의 병렬 제품 라인: Genium INET(복합 다자산 시장; SGX, HKEX, BrokerTec, Nasdaq Nordic에 배포)과 X-Stream INET(고성능 단일 자산 집중; SIX Swiss Exchange에 배포, <40 μs 매칭 달성). 매칭 지연시간이 밀리초에서 100 마이크로초 미만으로 개선
2016–2018 Nasdaq Financial Framework (NFF) 모듈형 플랫폼 아키텍처 도입; 단일 운영 핵심이 다수의 비즈니스 애플리케이션 구동; 마이크로서비스 모델 채택; 클라우드 배포 기능 추가
2018–2024 NFF 성숙 NFF를 은행 및 브로커에 확대; 엔진 최적화를 지속하여 40 μs 미만의 door-to-door 지연시간 달성; 시장 데이터 처리에 FPGA (현장프로그래머블게이트어레이) 가속 도입; 10G/40G 연결 확대
2024–현재 Nasdaq Eqlipse (4세대) 매매, 청산, CSD, 데이터 인텔리전스를 아우르는 통합 제품군; 클라우드 대응 플랫폼 위의 마이크로서비스 아키텍처; 다년 주기 릴리스를 대체하는 “에버그린” 분기별 업그레이드 모델; AWS 파트너십으로 하이브리드 클라우드 배포; Nasdaq Eqlipse Intelligence (클라우드 기반 분석/AI); 요하네스버그 증권거래소, Grupo BMV (멕시코), Nasdaq Nordic에 배포; 오사카거래소(OSE)가 차세대 파생상품 플랫폼으로 Eqlipse 선정 (2026년 2월 발표)

2. 아키텍처 (Architecture)

2.1 상위 수준 설계 (High-Level Design)

NASDAQ INET은 매매체결엔진 핵심에 단일 스레드, 이벤트 기반 아키텍처를 채택하여 엄격한 순서화를 통한 결정론적 주문 처리를 보장한다. 상위 Eqlipse 플랫폼은 이 핵심을 현대적 마이크로서비스 프레임워크로 감싼다.

설계 원칙: - 순수 전자 매칭 – 사람의 개입 없음 (NYSE와 달리 전문가/DMM 없음) - 엄격한 가격-시간 우선 – 주문은 가격 기준으로 먼저, 동일 가격 수준에서는 진입 시간 순으로 매칭 - 단일 스레드 매칭 – 하나의 스레드가 특정 종목의 모든 주문을 처리하여 락 경합을 제거하고 결정론적 동작 보장 - 커널 우회 네트워킹 – 사용자 공간 네트워킹 스택이 Linux 커널을 우회하여 컨텍스트 스위칭 오버헤드 제거 - 하드웨어 가속 – FPGA 카드가 핵심 피드 처리 및 파싱 작업 수행 - 불변 시퀀싱 – 모든 이벤트에 단조 증가하는 시퀀스 번호 할당, 신뢰할 수 있는 재생 및 복구 지원

데이터 흐름 (간략): 1. 주문이 게이트웨이(OUCH 프로토콜 (주문 입력 규약)/FIX/RASH/FLITE)를 통해 SoupBinTCP로 도착 2. 리스크/검증 확인 적용 (가격 합리성, 신용 한도, 과다주문 방지) 3. 주문이 종목별 매칭 스레드에 할당 4. 매매체결엔진이 가격-시간 우선 알고리즘 실행 5. 체결 보고서가 동일 프로토콜로 참가자에게 반환 6. 시장 데이터 업데이트가 ITCH 프로토콜 (시장 데이터 피드)을 통해 MoldUDP64(멀티캐스트) 및 SoupBinTCP(유니캐스트)로 발행

2.2 핵심 구성요소 (Core Components)

구성요소 기능 기술
INET 매매체결엔진 가격-시간 우선 알고리즘을 사용한 핵심 주문 매칭; 신규 주문, 취소, 수정 처리; 경매(시가/종가/거래중단 Cross) 처리 맞춤형 C/C++ 엔진; 종목별 단일 스레드; 커널 우회 네트워킹; 상용 Linux 서버에서 구동
주문 게이트웨이 참가자의 인바운드 주문 수신 및 검증; 프로토콜 변환(FIX → 내부 포맷); 세션 관리 및 인증 OUCH 4.2(네이티브 바이너리), FIX 4.0/4.1/4.2(업계 표준), RASH(라우팅 전략 지원 독자적), FLITE(FIX Lite – OUCH급 속도의 FIX 부분집합) 지원
시장 데이터 엔진 매매체결엔진 이벤트로부터 실시간 시장 데이터 생성 및 배포; 전체 호가잔량(TotalView) 및 BBO(Nasdaq Basic) ITCH 5.0 프로토콜; FPGA 가속 피드 생성; MoldUDP64 멀티캐스트 전달; SoupBinTCP 유니캐스트 옵션
FPGA 피드 핸들러 시장 데이터 메시지의 하드웨어 가속 파싱 및 생성; 최저 지연시간 데이터 경로 제공 맞춤형 FPGA 카드; 코로케이션 시설에서 10G 및 40G 연결로 이용 가능
경매 엔진 Opening Cross, Closing Cross, IPO Cross 및 Halt Cross 가격 발견 프로세스 관리 매매체결엔진에 통합; 경매 전 NOII(Net Order Imbalance Indicator) 배포
리스크 관리 게이트웨이 최대 주문 금액, 누적 금액 확인, 신용 노출 모니터링, 킬 스위치 등 사전 매매 리스크 통제 실시간 처리; 참가자별 구성 가능; 임계치 위반 시 자동 주문 취소
드롭 카피 서버 준법감시 및 대사를 위한 실시간 체결 사본을 참가자에게 제공 FIX DROP 프로토콜; MMID, INET 포트, SenderSubID별 필터링 구성 가능
세션/전송 계층 TCP 연결, 프레이밍, 시퀀싱, 하트비트, 인증, 메시지 복구 관리 SoupBinTCP 3.0/4.0 (점대점); MoldUDP64 (멀티캐스트); 갭 탐지 및 재생 제공
기준 데이터 서버 증권 마스터 데이터, 매매 일정, 시스템 이벤트 알림 배포 ITCH System Event 및 Stock Directory 메시지; 장 시작 전 매일 배포
감시 인터페이스 모든 주문 및 매매 활동의 실시간 피드를 Nasdaq MarketWatch 감시 시스템에 전달 Nasdaq SMARTS 감시 기술에 연동

2.3 기술 스택 (Technology Stack)

계층 기술
프로그래밍 언어 C/C++ (매매체결엔진 핵심, 게이트웨이 및 성능 핵심 구성요소)
운영체제 Linux (상용 서버; 저지연 최적화 커널: CPU 격리, NUMA 인식 할당, 인터럽트 어피니티, 틱리스 커널)
네트워킹 커널 우회 (사용자 공간 TCP/UDP 스택); Solarflare/Xilinx OpenOnload 또는 동급; OS 커널 네트워킹 오버헤드 제거
하드웨어 가속 시장 데이터 피드 처리 및 파싱용 FPGA 카드; 1 마이크로초 미만의 메시지 파싱
네트워크 장비 10 Gbps 및 40 Gbps 이더넷 연결; <35 ns 스위칭 지연시간의 40G Express Connect; 맞춤형 저지연 스위치
서버 하드웨어 고주파 Intel Xeon 프로세서; 상용 x86 서버; NUMA 최적화 메모리 배치
전송 프로토콜 SoupBinTCP 3.0/4.0 (신뢰성 있는 점대점), MoldUDP64 (재전송 기능이 있는 비신뢰성 멀티캐스트)
애플리케이션 프로토콜 OUCH 4.2 (주문 입력), ITCH 5.0 (시장 데이터), FIX 4.0/4.1/4.2 (주문 입력), RASH (라우팅 포함 주문 입력), FLITE (FIX Lite 주문 입력)
플랫폼 아키텍처 마이크로서비스 기반 (Eqlipse 계층); 컨테이너화된 서비스; 표준화된 API 제품군
클라우드 통합 AWS 파트너십; Carteret 데이터센터 내 AWS Outposts; 하이브리드 클라우드/온프레미스 배포; Nasdaq Eqlipse Trading 클라우드 플랫폼 (2025년 5월 출시)
데이터 및 분석 Nasdaq Eqlipse Intelligence – 클라우드 기반 데이터 수명주기 플랫폼(수집, 처리, 정제, 분석); AI/ML 통합 기능

6. 주요 기술적 특징 (Notable Technical Features)

6.1 순수 전자 시장 – 사람의 개입 없음 (Pure Electronic Market)

NYSE(DMM이 수동 개입 기능 보유)와 달리, NASDAQ INET은 매칭 프로세스에 사람의 개입이 전혀 없는 완전 자동화 매매체결엔진이다. 모든 주문 매칭, 경매 처리, 매매 체결이 알고리즘적으로 처리된다. 이는 사람의 의사결정과 관련된 지연시간 변동성을 제거하고 일관되고 결정론적인 처리 시간을 보장한다.

6.2 Opening 및 Closing Cross 경매 (Opening and Closing Cross Auctions)

INET의 경매 메커니즘은 모든 적격 주문을 집계하고 체결량을 극대화하는 단일 청산 가격을 결정한다. Net Order Imbalance Indicator (NOII)는 각 Cross 직전 수분 동안 배포되어 수급 동향에 대한 전례 없는 투명성을 제공한다. Closing Cross는 Nasdaq 일일 거래량의 약 16%를 처리하며, 뮤추얼펀드 NAV, 지수 산출 및 결제에 사용되는 공식 종가를 결정한다. 2025년 6월 Russell Reconstitution Cross는 0.871초 만에 1,024.55억 달러를 체결 – 역대 최대 기록이다.

6.3 Eqlipse “에버그린” 업그레이드 모델 (Eqlipse “Evergreen” Upgrade Model)

4세대 Eqlipse 플랫폼은 수년마다 주요 시스템을 업그레이드하던 전통적 접근방식을 대체하는 분기별 업그레이드 주기를 도입하였다. 이를 통해 파괴적인 이관 프로젝트 없이 개선사항, 보안 패치, 신규 기능의 지속적 배포가 가능하다. 고객 거래소는 예측 가능한 주기로 점진적 개선을 수령한다.

6.4 다자산, 다거래소 아키텍처 (Multi-Asset, Multi-Venue Architecture)

INET 매매체결엔진은 자산군에 구애받지 않으며 – 단일 핵심 기술로 주식, 채권, FX, 원자재, 파생상품, 디지털 자산, 탄소 배출권을 지원한다. 이 동일 엔진이 Nasdaq의 자체 18개 글로벌 거래소를 구동하며, 130개 이상의 외부 시장에 라이선스된다. Eqlipse 제품군은 이를 전체 매매 수명주기로 확장한다: 매매 → 청산 → CSD → 데이터 인텔리전스.

6.5 클라우드 하이브리드 배포 (Cloud-Hybrid Deployment)

Nasdaq의 AWS 파트너십은 지연시간 핵심 구성요소(매매체결엔진, 주문 게이트웨이)는 Carteret 온프레미스에 유지하면서 분석, 감시, 보고 및 비지연민감 서비스는 클라우드에서 구동하는 독특한 배포 모델을 구현한다. Carteret 데이터센터 내에 물리적으로 위치한 AWS Outposts가 두 환경을 원활하게 연결한다.

6.6 FPGA 가속 시장 데이터 (FPGA-Accelerated Market Data)

코로케이션 시설의 FPGA 카드는 하드웨어 가속 ITCH 피드 생성을 제공하여, 소프트웨어만으로는 달성할 수 없는 시장 데이터 지연시간을 실현한다. 이를 통해 코로케이션 참가자에게 호가장 변동에 대한 가능한 한 가장 빠른 시야를 제공한다.

6.7 성능 조정을 위한 프로토콜 계층 구조 (Protocol Hierarchy for Performance Tuning)

NASDAQ은 참가자가 지연시간/복잡성 간의 균형을 선택할 수 있도록 의도적인 프로토콜 스펙트럼을 제공한다: - OUCH – 최대 성능, 최소 유연성 (고빈도매매 (HFT) 회원사) - FLITE – FIX 의미론을 갖춘 OUCH 근접 속도 (FIX 워크플로우를 원하는 정교한 회원사) - RASH – 라우팅 전략을 지원하는 OUCH 유사 - FIX – 업계 표준, 가장 쉬운 통합, 가장 높은 지연시간 (기관 브로커)

모든 비OUCH 프로토콜은 게이트웨이에서 내부적으로 OUCH로 변환되므로, 매매체결엔진 자체는 하나의 네이티브 포맷만 처리한다.

6.8 24시간 매매 대비 (계획 중) (24-Hour Trading Readiness, Planned)

NASDAQ은 주 5일 23시간/일 매매 계획을 발표하였다(SEC 승인 대기, H2 2026 목표). Eqlipse 플랫폼의 24/7 운영 능력 – 이미 암호화폐 거래소 배포에서 검증 – 이 1시간의 일일 유지보수 창을 갖는 확장 세션 모델을 지원할 수 있는 위치에 있다.

주요 차별화 요소 (Key Differentiators)

NASDAQ INET 강점: - 지연시간 선도: ~14 μs door-to-door는 Exture+의 ≤ 70 μs 보다 약 5배 빠르며, NASDAQ의 집중적인 HFT 기반 최적화와 FPGA 가속을 반영 - 프로토콜 다양성: 4가지 주문 입력 프로토콜(OUCH, FIX, RASH, FLITE)이 명시적 성능/유연성 균형 제공 vs. KRX의 보다 표준화된 접근 모델 - 글로벌 기술 플랫폼: INET/Eqlipse 기술이 전 세계 130개 이상의 시장을 구동하여 대규모 규모의 경제와 지속적 개선 압력 창출 - 클라우드 하이브리드 혁신: AWS 파트너십 및 Outposts 통합이 거래소 인프라 현대화의 선도적 접근방식 - 코로케이션 생태계: 35 ns 미만 스위칭과 대규모 HFT 참가자 기반을 갖춘 Carteret 시설이 깊고 유동적인 생태계 조성

KRX Exture+ 강점: - 통합 다자산 플랫폼: 단일 시스템이 모든 자산군(주식, 파생상품, 채권, 원자재) 처리 vs. NASDAQ의 별도 주식/옵션 매매체결엔진 - 통합 가치사슬: KRX가 한국 전체 자본시장 인프라(거래소, 청산, 결제, 예탁)를 조율된 기술 스택으로 운영 - 종가 경매 설계: 종가 경매의 무작위 종료 시각 메커니즘이 NASDAQ의 고정 시간 Closing Cross보다 나은 조작 저항성 제공 - 단순한 접근 모델: KOSCOM을 통한 표준화된 연결이 국내 참가자의 복잡성 감소 - Solace 하드웨어 메시징: 전용 메시징 어플라이언스가 커널 우회 소프트웨어 스택의 복잡성 없이 보장된 결정론적 데이터 전달 제공

아키텍처 철학 차이: - NASDAQ INET은 분절된 시장에서의 최대 속도에 최적화되어 있다. 14개 미국 증권거래소 + 30개 이상의 다크풀이 경쟁하는 환경에서 주문 흐름을 유치하기 위해 가능한 최저 지연시간을 요구한다. - KRX Exture+는 통합 시장에서의 포괄적 커버리지에 최적화되어 있다. KRX가 유일한 거래소로서 운영되므로, 원시적 속도 경쟁보다 자산군 지원의 폭과 시스템 안정성을 우선시한다.
