1. 시스템 개요 (System Overview)

항목 세부 내용
시스템명 Millennium Exchange
운영 기관 London Stock Exchange Group (LSEG), MillenniumIT (LSEG 전액 출자 자회사, 스리랑카 콜롬보)가 개발 및 유지보수
목적 주식, ETF, 채권, 파생상품에 대한 주문 매칭, 시장 데이터 배포, 거래 보고를 제공하는 다자산 전자 매매 플랫폼
출시 연도 2011년 (2011년 2월 14일 LSE에서 가동; Turquoise는 2010년 10월 이관)
현재 버전 지속적 업그레이드; 최신 기능 릴리스 1.24.0 (2024년 8월); MIT201 매매시스템 가이드 Issue 15.7 (초안, 2024년)
개발 방식 자체 개발 – MillenniumIT가 개발, LSEG가 2009년 1,800만 파운드에 인수

시스템 변천사 (System Evolution)

기간 시스템명 주요 변경사항
1986년 이전 플로어 트레이딩 (공개호가) Royal Exchange와 이후 Stock Exchange Tower에서의 물리적 매매 플로어; 직업상 및 역할에 의한 엄격한 분리
1986–1997 SEAQ (Stock Exchange Automated Quotation) “빅뱅” 규제 완화 시 도입; 화면 기반 호가 표시 시스템; 경쟁 마켓메이커가 있는 호가 주도 시장; 전자 주문 매칭 없음
1997–2007 SETS (Stock Exchange Electronic Trading Service) LSE 최초의 전자 주문장; 가격/시간 우선 매칭의 주문 주도형; FTSE 100 종목에서 시작하여 점진적 확대
2007년 SETSqx 출시 정기 경매(SETS)와 연속 마켓메이커 호가(SEAQ)를 결합한 하이브리드 플랫폼; 저유동성 증권 대상 도입
2007–2011 TradElect Microsoft .NET 프레임워크, Windows Server 2003, SQL Server 2000 기반; Accenture 개발; ~10 ms 지연시간으로 출시했으나 부하 시 ~6 ms로 저하; 2008년 9월 7시간 장애를 포함한 안정성 문제 발생
2009년 MillenniumIT 인수 LSEG가 MillenniumIT (스리랑카)를 1,800만 파운드에 인수 (2009년 9월 16일 발표, 10월 19일 완료); TradElect를 Linux/C++ 플랫폼으로 대체하는 전략적 결정
2010년 10월 Turquoise 이관 Turquoise 다크풀이 Millennium Exchange로 이관; 평균 126 마이크로초 지연시간 달성 – 당시 세계 기록 주장
2011년 2월 Millennium Exchange 가동 (LSE) “빅뱅” 방식으로 2011년 2월 14일 TradElect를 완전 대체; 15개월의 테스트 후; SETS, SETSqx, SEAQ 모두 Millennium 플랫폼에서 운영
2012년 6월 Borsa Italiana 이관 Borsa Italiana 현물시장(ETFplus 포함)이 Millennium Exchange 플랫폼으로 이관
2014년–현재 글로벌 확장 40개 이상의 금융시장 인프라 기관에 배포; 통합 다자산 제공물인 Millennium Advanced Platform (MAP) 도입
2021년 3분기–2022년 8월 주 데이터센터 이전 LSEG가 런던 시티(레거시) 데이터센터에서 Isle of Dogs (Docklands) 신축 Telehouse 캠퍼스로 이전
2025년 3월 카사블랑카 증권거래소 CSE가 Millennium Exchange 및 Millennium Advanced Platform (MAP) 기반으로 주식 및 채권 거래 시작

2. 아키텍처 (Architecture)

2.1 상위 수준 설계 (High-Level Design)

  • 분산형, 이벤트 기반 아키텍처, 상용 하드웨어에서 구동
  • 온프레미스 배포, 전용 주 및 재해복구 데이터센터
  • 소프트웨어 기반 장애 대응 – 독점적 또는 전문 하드웨어에 의존하지 않음; 애플리케이션 수준의 이중화와 실시간 상태 복제를 통한 복원력 확보
  • 모듈형 설계 – 매매체결엔진, 게이트웨이, 시장 데이터 퍼블리셔, 감시, 리스크 관리가 별도이면서 긴밀히 통합된 구성요소로 운영
  • 다중 시장 기능 – 단일 플랫폼 인스턴스가 서로 다른 매매 모델(SETS, SETSqx, SEAQ)을 동시에 호스팅 가능

이 아키텍처는 고전적 거래소 설계 패턴을 따른다: 주문 입력 게이트웨이가 TCP/IP 연결을 통해 인바운드 주문을 수신 및 검증하고, 중앙 매매체결엔진으로 라우팅하여 가격/시간 우선 매칭을 실행하고 체결 보고서를 생성한다. 시장 데이터 퍼블리셔는 모든 호가장 이벤트를 포착하여 UDP 멀티캐스트를 통해 구독자에게 배포한다. Group Ticker Plant (GTP)는 지능형 스로틀링을 통해 거래소 전반의 데이터를 집계 및 정규화한다 – 지연시간에 민감한 메시지(체결, BBO 변경)는 단일 메시지 UDP 패킷으로, 비민감 메시지는 다중 메시지 패킷으로 일괄 전송한다.

2.2 핵심 구성요소 (Core Components)

구성요소 기능 기술
매매체결엔진 (Matching Engine) 연속매매 및 경매 메커니즘(시가, 종가, 변동성, 정기)에 대한 중앙 주문장 관리 및 가격/시간 우선 매칭; SETS, SETSqx, SEAQ 전반에서 다수의 동시 주문장 지원 SUSE Linux 위 C++; 인메모리 처리; 결정론적 실행 경로
Native Trading Gateway 회원사용 저지연 바이너리 주문 입력 인터페이스; 영속적 TCP/IP 세션을 통한 주문 제출, 정정, 취소, 체결 보고; Real Time Channel 및 Recovery Channel 지원 독자적 바이너리 프로토콜 (MIT203 사양); TCP/IP; ~126 마이크로초 평균 지연시간
FIX Trading Gateway FIX 프로토콜 5.0 SP2를 사용한 업계 표준 주문 입력 인터페이스; Native 게이트웨이와 동등한 기능에 더 넓은 호환성 FIX 5.0 SP2 프로토콜 (MIT202 사양); TCP/IP; ~196 마이크로초 평균 지연시간
Market Data Publisher (MITCH) Level 1(BBO, 체결) 및 Level 2(전체 호가잔량)를 포함한 주문별 전체 시장 데이터 배포; 동일 시퀀싱의 이중 피드(Feed A, Feed B) MITCH 프로토콜 (ITCH 변형, MIT303 사양); IPv4 위 UDP/IP 멀티캐스트
Group Ticker Plant (GTP) LSEG 거래소 전반의 시장 데이터 집계; 지능형 스로틀링 적용; 하위 소비자에게 데이터 정규화 및 배포 UDP 멀티캐스트; 비지연민감 데이터의 다중 메시지 패킷 일괄 처리
리스크 엔진 (Risk Engine) 최대 주문 금액/수량, 최대 총 대금, 가격 범위 확인, 메시지 스로틀링 등 사전 매매 리스크 통제; 회원사, 게이트웨이, 종목 그룹별 구성 가능 실시간 모니터링; GUI 기반 리스크 관리 인터페이스
Drop Copy Gateway 회원사에 체결 및 주문 상태 변경의 실시간 사본 전달 (사후 매매 대사 및 준법감시용) FIX 5.0 기반 (MIT205 사양); TCP/IP
감시 시스템 (Millennium Surveillance) 의심스러운 매매 패턴, 잠재적 시장 남용, 규정 위반에 대한 실시간 시장 모니터링 LSEG Technology 제품군 내 별도 제품; Millennium Exchange와 함께 배포
Reference Data Service 종목 정적 데이터, 호가 단위 표, 매매 일정, 기업행동 정보 배포 MIT401 사양; 일별 파일 기반 및 실시간 업데이트
킬 스위치 (Kill Switch) 특정 CompID, Native UserID 또는 전체 회원사의 모든 미체결 주문을 취소하는 비상 메커니즘; GUI 또는 전화로 접근 가능 리스크 관리 인터페이스에 통합; 전화 활성화 시 서면 후속 조치 필요

2.3 기술 스택 (Technology Stack)

계층 기술
프로그래밍 언어 C++ (핵심 매매체결엔진, 게이트웨이, 성능 핵심 구성요소)
운영체제 Novell SUSE Linux Enterprise (고빈도매매 (HFT) 용량 및 신뢰성을 위해 선정; TradElect에서 사용하던 Windows Server 대체)
하드웨어 상용 x86 서버 – Intel Xeon 프로세서 (출시 시 Xeon 5500 시리즈); 독점 하드웨어 종속성 없음; 표준 랙마운트 서버
네트워크 – 주문 입력 모든 매매 게이트웨이(Native 바이너리 및 FIX 5.0)용 TCP/IP; 점대점 영속적 연결
네트워크 – 시장 데이터 MITCH 시장 데이터 피드용 IPv4 위 UDP/IP 멀티캐스트; 이중 멀티캐스트 채널
네트워크 – 복구 시장 데이터 갭 복구를 위한 TCP/IP 리플레이 서비스 (최근 65,000건 메시지까지); 전체 상태 재구성을 위한 스냅샷 복구 서비스
데이터베이스 Oracle (기준 데이터 및 비지연민감 기능용) [미검증]
메시징/미들웨어 맞춤형 내부 메시징; 핵심 경로에서 서드파티 미들웨어 종속 없음

3. 성능 사양 (Performance Specifications)

지표 값 조건
평균 주문 입력 지연시간 (Native) 126 마이크로초 Native 바이너리 API (MIT203); 2010년 10월 Turquoise 출시 시 측정
평균 주문 입력 지연시간 (FIX) 196 마이크로초 FIX 5.0 SP2 API (MIT202); 출시 시 측정

성능 이력 (Performance History)

연도 지연시간 처리량 비고
1997년 (SETS) ~140 ms 현대 기준 낮은 수준 최초 전자 주문장; 당시 혁신적
2007년 (TradElect 출시) ~10 ms SETS 대비 개선 Microsoft .NET 플랫폼; Accenture 개발
2008–2010년 (TradElect 성능 저하) ~2.7–6 ms HFT 시대에 불충분 부하 시 성능 저하; 2008년 9월 7시간 장애; 경쟁사 Chi-X 0.4 ms, BATS 0.25 ms
2010년 10월 (Millennium – Turquoise) 126 마이크로초 세계 기록 주장 “경쟁사 대비 2배 빠름” – Chi-X 175 마이크로초, BATS Europe 250 마이크로초

맥락: 126 마이크로초 수치는 TradElect의 저하된 지연시간 대비 ~20배, 1997년 원래 SETS 시스템 대비 약 1,100배의 개선을 의미한다. 출시 당시 LSEG는 Millennium Exchange가 세계에서 가장 빠른 매매 플랫폼이라고 주장하였다.

5. 복원력 및 업무연속성 (Resilience & Business Continuity)

5.1 이중화 (Redundancy)

  • 소프트웨어 기반 장애 대응: 전문 하드웨어가 아닌 애플리케이션 계층에서 복원력 확보; 주 및 보조 매매체결엔진 인스턴스 간 실시간 상태 복제
  • Active-Passive 매매체결엔진 구성, 실시간 복제 [미검증 – 구체적 토폴로지 미공개]
  • 이중 시장 데이터 피드: Feed A 및 Feed B가 동일하게 시퀀싱; 구독자는 두 피드 모두 사용하여 클라이언트 측 중재 및 갭 탐지 가능, 한 피드에서 패킷 손실이 발생해도 데이터 손실 없이 보장
  • 다수의 매매 게이트웨이 인스턴스: 회원사는 이중화를 위해 다수의 게이트웨이를 통해 연결 가능
  • 단일 장애점 없음: 네트워크, 전력, 컴퓨팅 전반에 걸친 이중화

5.2 재해복구 (Disaster Recovery)

  • 주 데이터센터: Telehouse 캠퍼스, Isle of Dogs (런던 Docklands) – 2021년 3분기부터 2022년 8월까지 레거시 런던 시티 사이트에서 이전; LSEG 전용 시설
  • 레거시 주 사이트 (2022년 이전): 런던 시티 데이터센터 (2022년 8월 30일 폐쇄)
  • DR 사이트: 별도 지리적 위치 [구체적 주소 미공개]; 완전한 장애 전환 기능 제공
  • RPO/RTO: FCA 인가투자거래소 규제 기대에 부합; 구체적 수치 미공개
  • 네트워크 연결: EXA Infrastructure가 주 데이터센터로의 저지연 연결을 위한 온네트워크 다크 파이버, 파장, 이더넷 서비스 제공; BT Radianz, IPC/Connexus, TNS 등 기타 승인 네트워크 제공업체를 통한 추가 연결
  • DR 테스트: FCA 규정에 따라 정기적으로 실시; 회원사도 예정된 DR 훈련에 참여

데이터센터 지리에 대한 참고: 2022년 이전까지 LSE 매매체결엔진의 코로케이션은 런던 시티에 있었다. 일부 LSEG 관련 거래소(예: Turquoise)는 다양한 시점에서 Equinix LD4 (Slough)와 연관되었다. 2022년 이전 이후, LSE, Turquoise, Turquoise Europe의 주 시설은 Telehouse Docklands 캠퍼스이다.

5.3 용량 관리 (Capacity Management)

  • 수평적 확장성: 상용 서버 추가를 통해 확장하도록 설계; 수직적 확장이나 독점 하드웨어에 종속되지 않음
  • 용량 테스트: 주요 시장 이벤트(예: FTSE 지수 리밸런싱, IPO 출시) 전 정기적인 부하 및 스트레스 테스트
  • 구성 가능한 스로틀링: 개별 참가자의 시스템 과부하 방지를 위한 게이트웨이/CompID별 메시지 속도 제한
  • 지능형 시장 데이터 스로틀링: GTP가 비지연민감 메시지를 일괄 처리하여 대역폭 관리하면서 지연민감 메시지(체결, BBO 업데이트)는 즉시 전달 보장
  • 여유 용량 계획: 극단적 시장 상황에 대비하여 정상 피크 거래량을 상당히 상회하는 여유 용량으로 설계 [추정]

6. 주요 기술적 특징 (Notable Technical Features)

6.1 다중 시장, 다자산 플랫폼 (Multi-Market, Multi-Asset Platform)

Millennium Exchange는 단일 거래소 시스템이 아닌 – LSEG 그룹 전체에 배포되고 외부 거래소에 라이선스되는 플랫폼 기술이다. LSE 내에서만 세 가지 서로 다른 매매 모델이 동일 플랫폼에서 동시에 운영된다:

  • SETS: 가장 유동적인 종목(FTSE 100, FTSE 250, FTSE SmallCap)에 대한 순수 주문 주도 연속 매칭; 시가/종가/변동성 경매 지원
  • SETSqx: 저유동성 증권에 대한 정기 경매(08:00, 09:00, 11:00, 14:00, 16:35)와 연속 마켓메이커 호가를 결합한 하이브리드 모델

6.4 MillenniumIT 인수 – 전략적 의의 (MillenniumIT Acquisition – Strategic Significance)

2009년 1,800만 파운드에 이루어진 MillenniumIT 인수는 거래소 역사상 가장 중요한 기술 거래 중 하나로 널리 평가된다:

  • 배경: MillenniumIT는 1996년 스리랑카 콜롬보에서 Tony Weerasinghe (전 Oracle 국가 매니저)가 설립하였다. 이 회사는 우연히 거래소 기술에 진입하였다 – 콜롬보 증권거래소의 시스템 통합 계약이 완전한 직선처리(STP) 시스템을 구축하는 기회로 재해석되었다. 이것이 자본시장 소프트웨어 제품군의 기초가 되었다.
  • 동기: LSEG는 TradElect (Microsoft .NET 기반)의 실패로 극심한 압박을 받고 있었다. 성능 저하와 안정성 문제가 발생하였으며, Chi-X와 BATS가 저지연 플랫폼으로 시장 점유율을 빼앗고 있었다. LSEG는 자체 구축을 평가하였으나 인수가 더 빠르고 저렴하다고 판단하였다.
  • 영향: 1,800만 파운드 인수로 LSEG는 Accenture가 Microsoft 기술로 훨씬 높은 비용으로 구축한 시스템을 대체하는 플랫폼을 확보하였다. Millennium 플랫폼은 이후 전 세계 40개 이상의 시장에 배포되는 기술 라이선싱 사업의 중요한 수익원이 되었다.
  • 스리랑카 기술 허브: 콜롬보의 MillenniumIT 개발 센터는 LSEG 거래소 기술의 주요 엔지니어링 허브로 계속되어 수백 명의 엔지니어를 고용하였다. 2017년 LSEG는 MillenniumIT ESP의 엔터프라이즈 솔루션(비거래소) 사업을 Ambeon Holdings (Lanka Century Investments)에 매각하고, 거래소 소프트웨어 및 개발팀의 완전한 소유권을 유지하였다.

6.5 TradElect 실패 – 교훈 (TradElect Failure – Lessons Learned)

TradElect 경험(2007–2011)은 거래소 기술의 교훈적 사례이다:

  • Microsoft .NET, Windows Server 2003, HP ProLiant 블레이드 서버, Cisco 네트워킹, SQL Server 2000 기반
  • Accenture가 상당한 비용으로 개발 [정확한 금액 미공개]
  • ~10 ms 지연시간으로 출시 – 2007년에는 경쟁적이었으나 급속히 뒤처짐
  • 실제 시장 조건에서 ~2.7 ms 평균 지연시간으로 저하; 신흥 경쟁사보다 현저히 느림
  • 2008년 9월 8일 7시간 장애 발생 – 글로벌 금융위기 중 신뢰할 수 있는 매매가 가장 중요한 시기
  • 오픈소스 커뮤니티는 TradElect에서 Millennium으로의 이관을 미션 크리티컬하고 지연시간에 민감한 애플리케이션에서 Linux/C++가 Windows/.NET보다 우월하다는 증거로 지적

6.6 클라우드 배포 기능 (Cloud Deployment Capability)

2019년 AAX (디지털 자산 거래소)가 클라우드에서 Millennium Exchange를 구동하는 최초의 거래소로 출범하여, 이 플랫폼의 아키텍처가 전통적 온프레미스 데이터센터 환경 밖에서도 운영될 수 있음을 입증하였다. 이는 원래의 상용 하드웨어 온프레미스 모델에서의 진화를 의미한다.

주요 차별화 요소 (Key Differentiators)

  • 상업적 라이선싱 모델: Millennium Exchange의 Exture+ 대비 가장 특징적인 차별점은 글로벌 라이선싱 사업이다. Exture+가 KRX 전용으로 구축된 반면, Millennium Exchange는 6개 대륙 40개 이상의 시장에 배포된 상용 제품이다. 이는 LSEG에 상당한 기술 라이선싱 수익을 창출하며, 개선 사항이 모든 고객 거래소에 혜택을 주는 네트워크 효과를 만든다.

  • 인수 기반 혁신: LSEG의 MillenniumIT 인수(스리랑카에서 1,800만 파운드) 접근방식은 KRX가 자회사 KOSCOM을 통해 Exture+를 개발하는 접근방식과 대조된다. LSEG 모델은 놀랍도록 비용 효율적이었다 – 인수 가격은 TradElect 개발 비용의 일부에 불과했지만, 플랫폼은 우월한 것으로 입증되었다.

  • 지연시간 비교: 출시 시점에서 Exture+ (70 마이크로초, 2014년)는 Millennium Exchange의 공개 수치 (126 마이크로초, 2011년)보다 빨랐다. 그러나 양 거래소 모두 지속적으로 최적화해왔으며, 현재의 비교 수치는 공개되지 않고 있다. 출시 시 격차는 시점(Exture+가 3년 뒤 출시)과 Exture+의 메모리 기반 제로지연 매매체결엔진 설계 vs. Millennium의 상용 하드웨어 접근방식 모두를 반영할 수 있다.

  • 메시징 인프라: Exture+는 Solace PubSub+를 핵심 데이터 전달 인프라로 사용한다 – 금융 데이터에 최적화된 상용 메시징 어플라이언스/소프트웨어이다. Millennium Exchange는 핵심 경로에서 서드파티 미들웨어 종속이 없는 맞춤형 내부 메시징을 사용한다. 양 접근방식에는 트레이드오프가 있다: Solace는 입증된 초저지연 메시징을 기본 제공하고, 맞춤 메시징은 최대 통제와 벤더 종속 제거를 제공한다.

  • 다중 거래소 아키텍처: Millennium Exchange는 동일 플랫폼 인스턴스에서 서로 다른 시장 미시구조를 가진 다수의 매매 모델(SETS, SETSqx, SEAQ)을 네이티브로 운영할 수 있다. KRX는 모든 자산군을 Exture+에서 운영하되 보다 통합된 시장 모델을 가진다. 다중 모델 유연성은 LSEG의 다양한 거래소 환경(LSE, Turquoise, Borsa Italiana 각각 다른 시장 구조)에 가치 있다.
